Korvu Studio. estúdio

Um estúdio de Reels sobre Inteligência Artificial que roda inteiro num Mac: do tema à publicação no Instagram e no Facebook, e depois a leitura das métricas, que volta para o roteirista. Quem trabalha são agentes do Claude Code, cada um com um papel, mais scripts Python rodados com uv.

O apresentador grava; o resto é automático, com dois pontos de parada humanos: a aprovação da EDL (o corte) e a ida para a fila (06-publicar/). Não há servidor nem n8n, Zapier, Make ou ManyChat: o orquestrador é o próprio macOS, com cinco jobs do launchd, e a conversa com a Meta é HTTP direto na Graph API.

O caminho real de um dado: a palavra-chave até o direct

  1. O roteirista escreve cta_palavra no roteiro.md; o produtor-de-material gera o PDF em videos/<slug>/material/ (Chrome headless).

  2. O montar_pacote.py leva só esse PDF para 05-render-pronto/<slug>/material/.

  3. O publicador escreve no post.json o campo material = {palavra, arquivo, titulo, url: null}.

  4. Na hora, o publicar.py sobe o PDF para o R2 público e grava a URL em post.material.url; arquivo fora de material/ é recusado.

  5. Publicado o Reel, grava dm-material.json = {palavra, media_id_instagram, material_url}, que vai para 07-publicados/<slug>/.

  6. A cada 2 min o responder_comentarios.py lê esse arquivo, acha a palavra nos comentários, manda o direct com o link e depois responde em público.

Como o sistema conversa com a Meta

a API da Meta, passo a passo.

Tudo pela Graph API, com requests, no caminho Facebook Login (graph.facebook.com/v23.0). O Instagram busca o arquivo por URL pública no R2; o Facebook recebe o arquivo do disco. A Meta não guarda o agendamento: a hora mora no post.json. Comentários são lidos por consulta a cada 2 minutos, sem webhook.

Pré-requisitos que o código espera

  • Conta do Instagram profissional (Criador ou Empresa) e pública: “comentário de conta privada não chega à API”.
  • O Instagram ligado a uma Página do Facebook.
  • Um app na Meta for Developers, caminho Facebook Login (host graph.facebook.com, versão por META_GRAPH_VERSION, padrão v23.0); quem configura é administrador do app.
  • O caminho “API do Instagram com login do Instagram” (graph.instagram.com, tokens IGAA…) não é o que o código usa.

De onde a Meta busca o arquivo

  • Instagram, por URL: o script sobe para o Cloudflare R2 (API S3 via boto3) e passa video_url + cover_url (capa PNG → JPEG) no Reel, image_url (JPEG qualidade 95) em cada slide. Antes, HEAD na URL exigindo HTTP 200.
  • Facebook, do disco: “o robô do Facebook leva 403 da Cloudflare” no domínio público do R2 (13/10).
  • O PDF do material também vai ao R2: é o link do direct.

Token: tipo, validade e renovação

Como obter

  1. Graph API Explorer → escolher o app → gerar token com as permissões → escolher a Página e a conta do Instagram.
  2. Access Token Debugger → “Estender token de acesso” → token de usuário de longa duração (~60 dias).
  3. Com ele, GET me/accounts → id da Página (META_PAGE_ID) e access_token da Página; tirado de um token longo, “normalmente não expira”.
  4. GET {page-id}?fields=instagram_business_account → id = INSTAGRAM_USER_ID.
  5. INSTAGRAM_ACCESS_TOKEN “pode ser o mesmo token da Página”.
O token não renova sozinho.

Não há nenhuma chamada a oauth/access_token nem fb_exchange_token nos scripts. Os sinais são o aviso de “expira em menos de 7 dias” do verificar-tokens e o erro 190 (“token inválido ou expirado”). A renovação é manual, pelos passos 1 a 3.

Conferir sem publicar nada

uv run python scripts/publicar.py verificar-tokens chama /{ig-user-id}, /me, /{page-id} e /debug_token e mostra validade, tipo, expiração e escopos em falta; faz HEAD no R2. Os valores saem mascarados (4 primeiros caracteres + tamanho).

Segredos fora do log

Um filtro de logging tira os valores de INSTAGRAM_ACCESS_TOKEN, META_PAGE_ACCESS_TOKEN, META_APP_SECRET, R2_SECRET_ACCESS_KEY e R2_ACCESS_KEY_ID de qualquer mensagem. --dry-run percorre o fluxo inteiro e só imprime os pedidos.

Tudo local, sem terceiros

automação local.

Cinco jobs do launchd chamam scripts locais em intervalos fixos. A fila é uma pasta, o estado é JSON no disco, a agenda é o macOS. Em vez de a Meta avisar por webhook, o script pergunta.

Como é montado

  • Os .plist são modelos: instalar.sh troca __UV__, __PROJETO__ e __HOME__, valida com plutil -lint, copia para ~/Library/LaunchAgents/ e carrega com launchctl bootstrap + enable.
  • Cada job roda uv run --quiet python <script> na raiz, com ProcessType=Background, LANG=pt_BR.UTF-8 e PYTHONUNBUFFERED=1; saída e erro no mesmo log.
  • Forçar uma execução: launchctl kickstart -k gui/$(id -u)/<label>. Desinstalar: scripts/launchd/desinstalar.sh [label].
  • Notificações: osascript -e 'display notification …' (som “Glass”), só no macOS.
  • O macOS protege ~/Documents: se o log mostrar “Operation not permitted”, dê acesso a Pastas/Documentos ao binário do uv/python.

Do bruto ao pacote

metodologia de edição.

O corte segue o roteiro, linha a linha. A transcrição separa duas vozes, o alinhamento escolhe o melhor take, a EDL espera a aprovação humana, e só então o ffmpeg corta com zoom alternado. Depois vêm cor, Remotion, áudio a −14 LUFS, QA e pacote.

Antes de gravar

  • O roteiro vira roteiro.json (parse_roteiro.py), com linhas L01… e cenas extras E01….
  • Método “ChatGPT monitor”: o ChatGPT Voz, no alto-falante do celular, lê cada linha e o apresentador repete. O áudio tem duas vozes com o mesmo texto; o corte usa só a dele. Formatos: teleprompter.txt e monitor-chatgpt.txt.
  • Câmera em V-Log, 4K 25p 4:2:2 10-bit; o projeto inteiro roda a 25 fps (FPS_PROJETO).

Como o take é escolhido

  • Os takes só contam a voz dele e se separam por silêncio de pelo menos 1,5 s.
  • Escolhido = o último take limpo: similaridade com a linha ≥ 0,80 e sem falso começo, recomeço, final cortado ou voz da IA por cima → [OK].
  • Similaridade a partir de 0,45, ou improviso que cobre ≥ 55 % da linha → [PARAFRASE]; abaixo disso → [FALTANDO]. Confiança < 0,60 ou locutor incerto → [REVISAR].
  • Pontuação: similaridade 0,55 · cobertura 0,15 · fluência 0,10 · recência 0,10 · confiança 0,10.

Regras de corte

constantes do edl.py (valores de 01/10; o SKILL.md ainda mostra os antigos)

{{REGRAS_CORTE}}
ConstanteValorO que faz

Zoom: peças de câmera seguidas alternam 1.00 ↔ 1.12, com origem no rosto (Haar frontal do OpenCV; sem rosto, 50% 38%). A divisão de arquivo da câmera não conta como corte, e o que foi editado à mão é respeitado. No render, as peças caem na grade de frames (40 ms a 25 fps), com alças de áudio de 15 ms e cruzamento linear de 30 ms.

Cor, a 16 bits por canal

  • V-Log 10-bit
  • entrada V-Log → Rec.709
  • primária por take
  • LUT da marca
  • yuv420p bt709
  • grão (padrão 0)

Por segmento, a 16 bits por canal. A primária mede cada take depois da entrada e leva todos ao mesmo alvo da LUT, com limite de ±0,5 stop e ±8 % por canal. Um único look de marca em todos os vídeos. Gravação de tela, prints, imagens e animações nunca recebem cor. Saída H.264 CRF 16; a cor vai antes do Remotion.

Áudio, sem perdas até o fim

  • WAV 24-bit
  • compressor 1,5:1
  • −14 LUFS
  • limitador: teto = alvo − 0,3 dB
  • AAC 256k

Limiar do compressor = RMS da fala + 9 dB, ataque 30 ms, release 300 ms. O limitador roda a 192 kHz com teto 0,3 dB abaixo do alvo de true peak (−1,5 dBTP). Até 4 passadas corrigindo ganho e teto (tolerância ±0,3 LU). Nenhum EQ. Música em loop a −22 dB com ducking pela voz (sidechaincompress, ratio 8) e fade-out de 1,5 s. O vídeo não é recodificado.

QA automático (qa_check.py, dicionário SPEC) e um limite a conhecer

Reprova: resolução fora de 1080×1920, fps fora de FPS_PROJETO ±0,01 (25), codec que não seja H.264 High yuv420p, áudio que não seja AAC 48 kHz, duração fora de 3–900 s, sem faststart, > 300 MB, > 25 Mbps, loudness fora de −14 ±1 LUFS, true peak acima de −1,5 dBTP ou cena extra faltando. Só avisa: tags de cor, pretos ≥ 0,5 s, congelados ≥ 2 s, duração ±0,2 s da EDL, legendas × roteiro. O limite de 900 s é o de Reels da Meta, o mesmo do publicar.py (até 12/11 era 180 s).

Do zero

instalar e reusar.

Pré-requisitos: macOS (launchd, osascript, sips), Homebrew, uv, Python 3.12, ffmpeg + ffprobe, yt-dlp, Google Chrome (para o PDF), Node.js (Remotion) e Claude Code.

  1. Dependências

    uv sync
uv sync --extra local   # opcional: transcrição local (mlx-whisper, Apple Silicon)
cd remotion && npm install && cd ..

  2. Chaves

    Copie o modelo e preencha. Nunca versione o .env.

    cp .env.example .env
# ELEVENLABS_API_KEY · INSTAGRAM_* · META_* · R2_* · TZ_PUBLICACAO · FFMPEG_BIN · FFPROBE_BIN
uv run python scripts/verificar_setup.py

  3. Conferir a Meta e o R2 (não publica nada)

    uv run python scripts/publicar.py verificar-tokens
uv run python scripts/responder_comentarios.py verificar
uv run python scripts/metricas.py verificar

  4. Ensaio sem rede

    uv run python scripts/publicar.py --due --dry-run

  5. Ligar os agendadores

    bash scripts/launchd/instalar.sh            # os quatro (o do contexto tem instalador próprio); ou só um: instalar.sh uk.korvu.comentarios
bash estudio-contexto/launchd/instalar.sh   # o índice de contexto (precisa do Postgres do painel)

  6. Primeiro post real só com confirmação

    uv run python scripts/publicar.py publicar <slug> --sim

    Desligar: ativo: false em automacao-meta/respostas.yaml, ou bash scripts/launchd/desinstalar.sh <label>.
